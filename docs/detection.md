# 피로 감지 로직

카메라 없이 **차량 데이터만으로** 피로 점수(0~100)를 계산합니다.
코드: `app/src/main/java/com/hyundai/motor_rookie/fatigue/`

## 1. 입력 신호 (모두 0~1)

| 신호 | 의미 | 계산 |
|---|---|---|
| `s_time` | 연속 주행 시간 | 마지막 휴식(P단 5분 이상) 이후 경과 시간. 2시간에 1.0 |
| `s_steer` | 핸들 미세 보정 패턴 | 최근 60초 동안 ① 미세 보정 횟수가 평소보다 얼마나 줄었는지(60%) ② 급조작 횟수(40%) |
| `s_speed` | 속도 변동 | 최근 60초 속도 출렁임(1초 변화량의 표준편차)이 평소의 몇 배인지. 3배면 1.0 |
| `s_talk` | 대화 반응 | 퀴즈 무응답·오답·느린 응답이면 올라가고, 빠른 정답이면 내려감. 10분에 걸쳐 자연 감소 |
| `s_signal` | 순정 경고 | 10분 안에 FCW·LDW·DAW 1번 = 0.5, 2번 이상 = 1.0 |

### 핸들 미세 보정이란?
깨어 있는 운전자는 차선 안에서 핸들을 **좌우로 조금씩 계속** 바로잡습니다 (분당 10~20회).
졸리면 이 보정이 줄어들다가, 차가 쏠린 걸 뒤늦게 알아채고 **한 번에 크게** 꺾습니다.

- 미세 보정 = 1초 사이 0.3°~4° 움직임이면서 직전과 **방향이 바뀐** 경우
- 급조작 = 1초 사이 6° 이상 움직임

### 언제 계산하나요?
고속도로 정속 주행일 때만 계산합니다: 최근 60초 동안 **속도가 계속 60km/h 이상**이고, 최근 10초 동안 **급가속·급감속이 없을 때**.
시내 주행, 차선 변경, 진출로 감속 구간은 핸들이 원래 많이 움직여 졸음과 구분이 안 되기 때문입니다.
그 밖의 구간에서는 직전 값이 2분에 걸쳐 서서히 줄어듭니다.

### 운전자 기준선 (패턴 학습 간단 버전)
처음 15분 고속 주행에서 측정한 미세 보정 횟수와 속도 출렁임의 **중앙값**을 "이 운전자의 평소"로 저장합니다.
이후에는 평소 대비 변화로 점수를 매겨, 원래 핸들을 적게 움직이는 사람이 졸린 사람으로 오인되지 않게 합니다.

## 2. 점수 공식

```
raw = 0.25·s_time + 0.30·s_steer + 0.15·s_speed + 0.30·s_talk + 0.15·s_signal
F   = 100 × min(1, m × raw)
```

| 상황 가중치 m | 조건 | 값 |
|---|---|---|
| 야간 | 22시~06시 | ×1.2 |
| 비·눈 | 와이퍼 작동 | ×1.1 |
| 정체 | 최근 5분 평균 속도 1~30km/h (D단) | ×1.1 |
| 고속 직진 | 80km/h 이상 + 평균 핸들 각도 3° 미만 | ×1.1 |

점수가 1초마다 튀지 않도록 20초 이동 평균으로 부드럽게 만듭니다.

## 3. 단계

| 민감도 | 대화 | 공조 | 쉼터 |
|---|---|---|---|
| 낮음 | 45 | 65 | 80 |
| **보통 (기본)** | **40** | **60** | **75** |
| 높음 | 35 | 55 | 70 |

- 올라갈 때는 기준을 넘는 즉시, 내려갈 때는 기준보다 5점 더 낮아져야 내려갑니다.
- P단 5분 이상(또는 파워냅 종료)이면 휴식으로 보고 0부터 다시 셉니다.

## 4. 시뮬레이션 결과 (drowsy_drive.csv, 야간 23시 출발)

| 주행 시간 | 상태 | 점수 | 단계 |
|---|---|---|---|
| 0~95분 | 정상 주행 | 0 → 약 30 (주행 시간·야간 가중치로 서서히 상승) | 관찰 |
| 약 106분 | 서서히 졸림 (보정 감소, 속도 출렁임) | 40 | **대화** |
| 약 109분 | | 60 | **공조** |
| 약 113분 | 심하게 졸림 (급조작, 차선 이탈 경고) | 75 | **쉼터 안내** |
| 154분 | 쉼터에서 P단 5분 | 0 | 관찰 |

`normal_drive.csv`(졸음 없음)는 2시간 30분 동안 최고 약 36점으로 **대화 단계까지 올라가지 않습니다.**
실제 시연에서는 여기에 퀴즈 반응(`s_talk`)이 더해져 단계가 더 자연스럽게 이어집니다.

## 5. 한계
- 카메라를 쓰지 않으므로 눈 감김을 직접 보지 못합니다. "졸음 진단"이 아니라 **"말을 걸 타이밍 추천"**입니다.
- 시뮬레이션 데이터는 졸음 운전의 일반적인 패턴(보정 감소·급조작·속도 출렁임)을 흉내 낸 것으로, 실제 주행 데이터로 기준값을 다시 맞춰야 합니다.
